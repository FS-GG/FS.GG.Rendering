# Phase 1 Data Model: Audio effect surface

Feature `243-audio-effect-surface`. Entities are pure F# values in the `FS.GG.UI.Canvas`
namespace (module `Audio`). See `contracts/Audio.fsi` for the exact signatures.

## Entities

### `AudioEffect` (discriminated union)

A requested sound action, emitted as a value from a product's pure `update`. Data only — never a
device handle, callback, or IO.

| Case | Fields | Meaning |
|------|--------|---------|
| `PlaySfx` | `sound: SoundId`, `volume: float` | Play a one-shot sound effect at a normalized gain. |
| `PlayMusic` | `track: TrackId`, `loop: bool` | Start a music track, optionally looping. Supersedes any current track. |
| `StopMusic` | — | Stop the current music track. No-op if nothing is playing. |
| `SetMasterVolume` | `level: float` | Set the master gain (normalized). |

**Validation rules**:
- `volume` / `level` are normalized to `[0.0, 1.0]`; out-of-range values are **clamped** by the
  interpreter/smart constructors — never rejected or thrown on (Principle VI).
- The DU carries only plain data; no case references a device, stream, or effectful closure.

**Notes**: The vocabulary is intentionally minimal (the game-default gap). Richer audio (spatial,
ducking, DSP) is a future **additive** DU extension and does not change the record-only interpreter
seam.

### `SoundId` / `TrackId` (single-case DUs over `string`)

Opaque, product-owned identifiers naming a sound or music track. The framework does **not** own the
id → asset mapping (kept out of the library, mirroring how per-game stat mapping is kept out of
symbology). A product resolves these to real assets in its own host layer.

### `AudioEvidence` (record)

Ordered proof of what a product requested, produced by the record-only interpreter.

| Field | Type | Meaning |
|-------|------|---------|
| `Requested` | `AudioEffect list` | Requested effects in dispatch order (oldest first), with volumes normalized. |

**State transition**: `emptyEvidence` → `record e1` → `record e2` → … accumulates in order.
`interpret [e1; e2; …]` is the batch fold producing the final `AudioEvidence`. This is the
headless-safe host boundary for the minimal slice: no device access, never blocks, never throws
(FR-004/FR-005). It is **real** evidence of requests (not synthetic sound), so no `Synthetic`
disclosure applies.

## Relationships & boundaries

```
product update  ──emits──▶  AudioEffect  ──record/interpret──▶  AudioEvidence  ──asserted by──▶ tests
                                   │
                                   └──(deferred)──▶ real audio backend in SkiaViewer host
                                        (consumes the same AudioEffect values; surface unchanged)
```

- **Owned by this feature**: `AudioEffect`, `SoundId`, `TrackId`, `AudioEvidence`, module `Audio`.
- **Not owned**: id→asset resolution (product), real sound output (deferred backend).
- **Package placement**: all of the above live in `FS.GG.UI.Canvas` (module `Audio`), Scene-only,
  no new dependency. Delivered to `game`/`sample-pack` products via the existing Canvas package
  gate.
