# THE MIRROR-OMISSION LEDGER (#752)
#
# `<kind> <package>::<namespace>.<Name>`, one per line — `kind` is `type` or `module`. `#` comments and blank lines are ignored.
#
# WHAT AN ENTRY MEANS. "The pinned package exports this type, in a namespace `docs/api-surface/` DECLARES,
# and the mirror does not declare it." Nothing else. It is not an excuse and it is not a decision that the
# type SHOULD be absent — it is the record of a gap, so that the gap is countable and in the diff rather
# than invisible.
#
# WHY IT EXISTS. Every other rule in `TemplateConsumesPinnedApiTests.fs` judges MIRROR ⊆ PIN — "the mirror
# declares this; does the pin export it?". Nobody ever asked the converse. So the mirror could omit a type,
# or a whole file, and every gate reported green: an omission declares nothing, and a rule that only judges
# declarations has nothing to judge. At $(FsGgUiVersion)=0.9.2 the mirror was missing 285 of the 673 public
# types the pinned packages export, with CI green and nothing ledgered. The rule that closes that hole lands
# on a repo that already violates it 285 times, and the two honest options are to fix them all or to record
# them. Narrowing the rule until it is green is not one of them.
#
# So: this file is the DEBT, and it is meant to shrink to nothing. #694's mirror generator is what pays it
# off wholesale; until then, no NEW omission can land, which is the entire point.
#
# IT IS A RATCHET, NOT A DUMPING GROUND. Two rules keep it one:
#   * an entry the mirror NOW declares      -> the gap was closed. Delete the line.   (stale)
#   * an entry the pin NO LONGER exports    -> the type was cut.   Delete the line.   (phantom)
#
# ADDING A LINE IS A DECISION, AND IT NEEDS A REASON. A deliberate curation (the mirror is a curated
# contract, not a dump) is a legitimate entry — say so, next to it. An omission you simply have not got to
# is also a legitimate entry, for now. An omission you added BECAUSE the gate went red is not.
#
# NOTE the typed front door (`FS.GG.UI.Controls.Typed.*`, feature 085 FR-013) is NOT here and must not be:
# no mirror file declares that namespace, so it is out of the rule's scope structurally. Entries here are
# types in namespaces the mirror DOES claim.

# THE DEVICE LANE OF FS.GG.Audio.Host — a DELIBERATE curation, and the ceiling is raised 373 -> 382 in
# the same commit to say so out loud (#752).
#
# Audio 0.3.0 added a device/diagnostics surface to a namespace the mirror already declares. The mirror
# teaches the half a scaffolded product actually uses — the headless, record-only one: `AssetResolver`,
# `IAudioBackend`, `IMixingBackend`, `Wav`, `Spatial`. `Backend`, `DeviceDiagnostics` and
# `AssetDiagnostics` (with the types they carry) drive and diagnose a real device, and the scaffold does
# not: `fs-gg-product-audio` is explicit that a product emits audio as PURE VALUES recorded at the host
# boundary, with no device call in `update`. Mirroring them would teach a lane the product has no way to
# reach, and would put device-lane prose in the one skill that exists to keep the device out.
#
# HOW IT ARRIVED UNDECLARED, which is the part worth fixing elsewhere: this rule reads the PINNED
# package, and a release publishes the very packages it pins — so on the release commit the read fails,
# `withPinnedSurface` defers it as ReleasePending, and the gate is green. That is correct (a release
# cannot be blocked on a package it has not pushed yet). Nothing re-asks after the publish, so the debt
# lands on whoever opens the next PR — here, #752, which had not touched Audio at all.
