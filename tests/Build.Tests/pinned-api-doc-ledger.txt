# pinned-api-doc-ledger — declared violations of the doc-vs-PIN rule (#589).
#
# THE RULE. No shipped template doc may name an `FS.GG.*` symbol that is absent from the package
# version a scaffolded product restores ($(FsGgUiVersion) et al, template/base/Directory.Packages.props).
# A reader who copies the block gets a hard build error. That is #550, and the rule is asserted by
# `TemplateConsumesPinnedApiTests`.
#
# WHAT THIS FILE IS FOR. The rule landed on a repo that already violated it. Narrowing the rule until it
# went green would have been the quiet choice and the wrong one, so the violations are DECLARED instead:
# a gap must be a decision somebody made, not an omission nobody noticed. Same idiom, same reason, as
# S-DOC's `tests/Package.Tests/surface-doc-ledger.txt`.
#
# AN ENTRY IS NOT AN EXCUSE — IT IS A DEBT, AND IT NAMES ITS CREDITOR. Every line carries the issue that
# retires it. A line with nobody's name on it is a line that never leaves.
#
# IT IS A RATCHET. Two rules keep it shrinking, and both are asserted:
#   * the pin NOW exports the symbol   -> the release landed. Delete the line.   (stale)
#   * no shipped doc names it any more -> the doc was fixed.  Delete the line.   (phantom)
#
# The phantom rule is why this file cannot re-open the very bug it records. #587 will publish
# `interpretRecordOnly`, and someone will then re-apply that spelling to the docs #550 reverted. If they
# re-apply it EARLY, a dead ledger entry would wave the build error straight back through — so a ledger
# entry is not allowed to outlive its subject.
#
# FORMAT: <repo-relative doc path>::<Module.member>     (one per line; `#` comments and blanks ignored)
#         <repo-relative doc path>::<Type.case-or-field>  — same shape, judged against the pin's TYPES (#611)
#
# NOT LISTED, DELIBERATELY: `Persistence.interpretRecordOnly` — the instance this rule was written for.
# It is NOT here because it is FIXED: #550 (PR #590) removed it from both shipped docs, and this rule was
# red on exactly those two sites until that merged. Ledgering it would have been wrong twice over — the
# entry would have gone PHANTOM on their merge and reddened `main` for a fix that was correct, and a debt
# that is paid does not belong in a ledger. It is named here only so the next reader knows the rule has

# NOT LISTED, DELIBERATELY: `ViewerKeyboard.mapKeyRaw` — ledgered by #589, retired by #591 (PHANTOM).
# It was ledgered on the belief that the CAPABILITY was unreleased, so only a release could retire it.
# That was wrong, and worth recording because the mistake is an easy one to repeat: `mapKeyRaw` is sugar,
#
#     let mapKeyRaw onKey = fun key isDown -> onKey (toKeyId key) isDown

# and `toKeyId` DOES ship in 0.9.0. `MapKey` is only a function, so a product writes that lambda itself
# and loses nothing — the rebind section now teaches the lambda, and both LEDGERED sites are gone. The
# lesson: an absent HELPER is not an absent capability. Before ledgering a symbol, check whether the pin
# already exports what it is made of.
#
# THE DEBT IS PAID, AND THE RULE CAN NOW SEE THE CLASS IT COULD NOT (#598). The paragraph that stood here
# recorded a `mapKeyRaw` this rule was structurally BLIND to: a `///` comment in
# Controls.Elmish/ControlsElmish.fsi telling a product author to set `MapKey` to it. The extractor read
# `val` declarations and ```fsharp fences and nothing else, so it was green on that site and always would
# have been — ledgering it would not have helped, because the extractor never looked there.
#
# #598 fixed BOTH halves. The doc now teaches the lambda `mapKeyRaw` was sugar for
# (`fun key isDown -> Some(YourMsg(ViewerKeyboard.toKeyId key, isDown))`), in src/Controls.Elmish so the
# exact-copy mirror follows, and in the runtime diagnostic that carried the same instruction. And the
# extractor now reads `///` doc-comments of the shipped mirror, so the next one cannot hide there.
#
# WIDENING IT FOUND MORE, WHICH IS THE POINT: 13 doc-comments in Controls/Control.fsi taught
# `Attr.onClick` / `Attr.onChanged` / `Attr.onSelected` / `Attr.checked'` — a module that exports none of
